# 공개 접근과 AI 사용량 정책

2026년 11월 10일 적용 정책이다. 관측 기록, 등록 얼굴, 검출 사진과 AI 질문은 로그인 없이 이용할 수 있다. 일반 로그인 계정에도 같은 조회와 질문 권한을 제공한다. 관측 등록, 인물 확인 저장, 프로필 및 사진 변경은 지정 운영자 권한을 사용한다.

## 로그인과 대화

로그인 실패 횟수 제한은 해제했다. LOGIN_RATE_LIMIT_ENABLED의 기본값은 False다. 관리자 로그인과 CSRF 및 세션 검증은 유지한다. 비로그인 방문자의 대화 기록은 브라우저 세션에 연결한 임의의 식별자로 분리하고 로그인 계정의 대화도 계정별로 분리한다. 다른 방문자의 대화 ID를 알아도 해당 대화를 조회하거나 이어서 질문할 수 없다.

브라우저의 질문 및 대화 생성 POST에는 유효한 CSRF 토큰이 필요하다. 정상 API 토큰 인증은 기존 Android 및 Edge 연동과 호환된다. 사용량과 임베딩 문서 관리 API는 운영자 권한을 사용한다.

## AI 한도

AI 설명 생성은 서버 전체 하루 10회, 텍스트 임베딩은 하루 100회다. HISTORY_LLM_DAILY_LIMIT와 HISTORY_EMBEDDING_DAILY_LIMIT로 설정하며 한국 시간 자정에 새 날짜의 한도를 적용한다. 실제 외부 요청 시도를 집계하므로 공급자 오류나 타임아웃도 한 번으로 계산한다. 자동 재시도로 추가 호출하지 않는다.

캐시된 질문 벡터, 완료된 질문의 재전송과 대화 복원은 새 유료 요청으로 집계하지 않는다. 한도에 도달하면 정확한 DB 집계와 근거를 반환하고 한도 도달 상태를 표시한다. 0은 해당 외부 호출 중지이며 유효 설정 범위는 0부터 10000까지다. 운영자는 /api/v1/history/usage/에서 한도와 사용량 및 로그인 제한 해제 상태를 조회한다.

## 검증과 저장

카운터는 비공개 SQLite에 저장하고 여러 WSGI 작업자 간 요청을 트랜잭션으로 직렬화한다. 브라우저 세션을 바꾸어도 서버 전체 하루 10회 한도는 초기화되지 않는다. 기존 원본 사진과 운영자 대화는 보존한다.

이전 공개 접근 적용 시 WSL에서 python PhotoBlogServer/tools/verify_security.py로 전체 283개와 별도 HTTP 엔진 15개를 확인했다. HTTP 15개는 전체의 재실행 부분집합이다. 새 공개 접근 검사 6개는 방문자 대화 분리, CSRF, 운영자 변경 권한과 서로 다른 방문자 사이의 5회 상한을 확인한다. 실제 유료 모델 호출은 0회다.

## 운영 반영

배포 도구는 tools/deployment/deploy_security_patch.py다. 기존 공식 API 인증을 사용하며 API와 프로그램 검증 요청은 최소 5초 간격으로 보낸다. 원격 백업과 해시를 확인한 뒤 변경하고, DB 스키마와 의존성 및 기존 사진과 게시글을 유지한다.

실제 반영과 한도 확인은 evidence/security/deployment.json, 로컬 실행 근거는 evidence/content/server/verification.json에 있다. 브라우저 캡처는 evidence/screenshots/basic-20261110에 보관한다. 새로운 유료 모델 시험은 사용자 별도 승인을 받은 범위에서만 실시한다.
## 10회 정책과 일회성 초기화

2026년 11월 10일 사용자 요청으로 기본 생성 한도를 10회로 변경했다. WSL에서 Django 302개와 부분집합 HTTP 15개를 재실행했고, 방문자 11명의 모의 요청에서 10회까지 허용하고 11번째 외부 호출을 차단했다. 오늘 생성 사용량은 5회에서 0회로 한 번 초기화했다. 임베딩 사용량과 과거 날짜의 사용량, 대화와 관측 자료 및 공급자의 실제 요금은 유지했다. 초기화 전 카운터 DB를 비공개로 백업했고 재시작 시 재초기화되지 않는 것을 임시 WSL DB로 확인했다. 운영 적용과 사용량 조회는 evidence/security/generation-limit-10-20261110.json에 있다. 새 유료 모델 호출은 0회다.
