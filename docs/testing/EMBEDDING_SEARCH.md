# 관측 기록 의미 검색

영상 실행마다 저장된 설명, 인물 확인 상태, 촬영일과 분석일을 하나의 텍스트 문서로 만든다. 사진이나 얼굴 특징 벡터를 임베딩 API에 보내지 않는다. 촬영 시각이 없는 자료는 미상으로 유지한다. 옷차림이나 영상 속 행동을 새로 분석하는 기능은 포함하지 않는다.

기존 서버 추가 기능인 인물 이력과 근거 질의의 검색 방법을 확장한 것이다. 공통평가 02의 추가 기능은 기존 두 개를 유지한다. PythonAnywhere에서 Python 표준 라이브러리로 벡터를 읽고 코사인 유사도를 계산한다. 별도 벡터 서버나 모델 학습, 새로운 서버 패키지가 필요하지 않다.

## 검색과 집계

인물, 기간, 영상 실행 조건을 먼저 DB에 적용한다. 조건 안의 영상만 의미 검색 후보가 된다. `text-embedding-3-small`의 512차원 텍스트 벡터를 사용한다. 벡터 유사도와 제목 일치를 0.75와 0.25 비율로 결합하고, 결합 점수 0.30 이상인 영상 중 최대 5개를 선택한다. 제목은 문자 묶음과 출국, 입국, 보도, 안보, 회의, 보행, 연설, 행사에 관한 작은 용어 목록으로 비교한다. 이 용어는 영상 설명의 검색 보조이며 사진에 새로운 사실을 붙이는 분류 결과가 아니다. 유사도와 결합 점수는 신원 확률이나 사람 판정 정확도가 아니다.

선택된 영상에 한해 기존 DB 집계와 근거 사진을 만든다. 집계는 의미 검색으로 선택한 일부 영상의 기록임을 표시한다. 전체 조회의 집계와 혼동하지 않도록 AI 설명에도 검색 범위를 전달한다. 얼굴 후보가 확인된 인물로 바뀌는 일은 없다.

색인은 `HISTORY_MEDIA_ROOT/.semantic-index.json`에 저장한다. 문서의 내용 해시로 누락과 변경을 검사한다. 자료 추가나 인물 확인으로 내용이 달라지면 오래된 벡터로 검색하지 않고 조건 조회 결과와 안내를 표시한다. 삭제된 영상은 DB 조건에서 제외된다. 이름 변경과 인물 확인도 색인 변경 대상이다.

## API 사용과 승인

사용자가 테스트 모델 API를 호출하기 전에 허락을 받도록 요청했다. 실제 호출 전에는 대상 문서 수, 질문 수와 요청 수를 제시한다. 자동 테스트와 화면 캡처는 가짜 응답을 사용한다. 실제 테스트를 승인받았다고 해서 추가 호출이나 자동 재시도를 허용한 것으로 해석하지 않는다.

2026년 11월 9일 운영자의 명시적 승인에 따라 웹과 Android의 의미 검색 및 AI 설명 토글을 없앴다. 사용자가 직접 보내기를 누를 때만 질문 임베딩 최대 1회와 AI 답변 최대 1회를 자동 사용한다. 페이지 열기, 대화 기록 조회, 새 대화 선택은 모델을 호출하지 않는다. Codex가 실행하는 유료 테스트는 별도 승인이 필요하다. 같은 질문의 임베딩은 비공개 캐시에 저장해 재사용한다. 실패해도 자동 재시도하지 않는다. 캐시는 모델과 차원, 정규화한 질문의 해시로 구분한다. 동시에 같은 캐시를 처리할 때는 파일 잠금으로 중복 호출을 막는다.

색인은 웹 요청이나 사진 수신 시 자동으로 생성하지 않는다. 운영 도구 `tools/build_embedding_index.py`는 기본적으로 실행 계획만 출력한다. 실제 생성에는 `--apply --allow-paid-api --max-api-calls N`이 필요하다. 문서와 테스트 질문을 한 배치로 묶을 수 있고 기존 벡터는 재사용한다. 토큰과 인증 값은 소스나 산출물에 저장하지 않는다.

`POST /api/v1/history/ask/`의 `cache_only: true`는 캐시 미스 때 임베딩 호출을 금지한다. 이 모드에서 `generate: true`는 400으로 거부한다. 승인 후 만든 벡터를 운영에 올린 뒤에도 검증은 이 모드로 진행해 추가 모델 호출을 막는다.

## 검증

WSL 단위 테스트는 승인 없는 호출 금지, 배치 순서와 벡터 검증, 색인 재사용, 날짜와 인물 조건 보존, 오래된 색인 처리, 캐시 잠금, 외부 오류 및 호출 횟수, 근거 없는 결과 제외, 권한을 검사한다. 제어된 테스트 벡터는 검색과 필터의 정확성을 검증하며 실제 모델의 한국어 검색 품질을 입증하는 자료로 취급하지 않는다.

모바일 웹과 Android에서는 대화 기록, 근거 사진, 실제 키보드 상태와 작은 화면의 보내기 버튼을 확인한다. UI 테스트 서버는 의미 검색과 LLM을 가짜 응답으로 바꾸고 임베딩 전송 함수는 차단한다. HTTP API의 semantic 및 generate 기본값은 false를 유지하며, 운영 검증 도구는 cache_only와 generate:false를 명시한다.

실제 모델 검증은 미리 정한 출국, 기자 설명, 국제 안보 회의 질문 세 개를 사용한다. 문서와 이 질문들을 한 번에 임베딩한 뒤 캐시 전용으로 운영 검색을 검사한다. 세 질문 결과는 고정 예제의 확인이며 일반 정확도나 전체 영상 인식 성능으로 보고하지 않는다. 실제 호출 전에는 사용자 승인이 필요하다.

최초 벡터 단독 검색은 세 질문 중 두 질문에서 관련 출처를 찾았고 출국 질문에서 보행자 영상을 잘못 골랐다. 초기 결과는 `evidence/history/embedding-cloud-initial.json`에 보존했다. 같은 벡터를 재사용해 제목 검색을 결합했으며 추가 임베딩 요청은 하지 않는다. 수정한 정렬 기준은 프로토콜 2에 명시했다. 최초 결과를 수정된 기준으로 검증한 결과와 바꿔 쓰지 않는다.

규격은 [OpenAI 임베딩 API 문서](https://developers.openai.com/api/reference/resources/embeddings/methods/create)를 참고했다. 최신 실행 결과는 `evidence/history/embedding-build.json`, `evidence/history/embedding-cloud.json`, `evidence/ui-audit/embedding-deployment.json`에 기록한다.


최종 확인: 사용자가 승인한 임베딩 요청 1회에서 4,814토큰을 사용했다. 문서 31개와 질문 3개의 벡터를 만들었고 이후 추가 모델 요청은 하지 않았다. 제목 혼합 정렬의 운영 검색은 고정 질문 3개에서 관련 출처를 찾았다. WSL Django 231개와 실제 로컬 HTTP 15개, 웹 단위 72개, Windows Android JVM 40개와 두 크기의 기기 검사가 통과했다. 운영 브라우저에서도 캐시된 출국 질문으로 일본 출국 영상과 근거 사진을 확인했다. 최신 배포는 202611081909202100d8이며 결과와 화면 해시는 evidence/history/embedding-summary.json에 있다.
