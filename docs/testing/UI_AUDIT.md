# 공통평가 02 모바일 화면 개선

2026년 11월 8일. 프로젝트 1에서 받은 피드백을 기준으로 기존 화면을 Android에서 먼저 캡처하고, 수정 후 같은 크기에서 비교한다. Android 네이티브 앱과 Android WebView의 모바일 웹을 각각 검사한다. 웹 페이지 검사 도구로 제품 앱을 대체하지 않는다.

## 개선 기준

- 목록은 검색 폼보다 사진을 먼저 찾을 수 있어야 한다. 여러 사진을 두 열로 보여주고 보조 필터는 필요할 때 연다.
- 편집은 사진과 주요 도구, 완료 버튼을 작업 화면 안에서 사용한다. 짧은 화면과 키보드가 열린 상태도 확인한다.
- 글 작성, 태그, 검색 문구를 구분하고 같은 입력 요소를 여러 번 나열하지 않는다. 사용자의 입력과 선택 상태를 보존한다.
- 관측 기록은 같은 시점의 연속 사진을 묶어 대표 장면을 보여준다. 묶음의 원본 기록은 모두 열 수 있어야 하며 사람의 신원을 합치는 것으로 처리하지 않는다.
- 질문 답변은 짧은 결론과 근거 사진을 먼저 보여준다. 정식 DB 집계와 전체 근거는 펼쳐서 확인할 수 있게 한다.
- 얼굴 후보와 운영자 확인 상태를 글자로 구분한다. 유사도 점수를 사람일 확률로 설명하지 않는다.
- 공통 메뉴의 현재 위치, 버튼과 입력창의 모양을 앱과 웹에서 맞춘다. 필수 사진 블로그, 업로드와 동기화 기능을 유지한다.

## 검사 범위

비회원과 운영자 목록, 빈 검색 결과, 로그인, 사진 상세, 사진 선택, 얼굴 편집, 글 작성, 태그, 검색 문구, 실제 키보드, 관측 목록과 조건, 인물 확인, 질문과 답변을 확인한다. 개발용 API 및 모델 검사 화면은 일반 사용자 페이지와 구분한다.

검사 서버는 기존 로컬 검증 DB를 복사해 사용한다. 운영 데이터와 이전 검증 DB를 수정하지 않는다. UI 검사의 AI 응답은 명시한 고정 예제이며 외부 API를 호출하지 않는다. 실제 OpenAI 연결은 `evidence/history/llm-verification.json`의 별도 검사로 확인했다.

## 변경 전 관찰과 수정 대상

| 화면 | 관찰한 문제 | 수정 방향 |
| --- | --- | --- |
| 앱 공통 메뉴 | 큰 버튼과 여백, 선택한 메뉴 구분 부족 | 짧은 헤더와 명확한 현재 위치 |
| 사진 목록 | 필터와 새로고침 버튼이 사진 앞의 공간을 차지함 | 한 줄 검색과 접는 필터, 사진 중심 카드 |
| 사진 상세 | 수정과 삭제가 본문 뒤에 있고 웹의 수정 동작이 중복됨 | 상단 메뉴에 조작 모으기, 사진과 본문을 읽기 쉽게 배치 |
| 로그인 | 앱의 인증 오류가 대화상자 뒤 상태줄에 표시됨 | 입력란 가까이에 오류 표시, 키보드에서도 제출 가능 |
| 관측 목록 | 가까운 시점의 사진이 반복되고 후보 ID가 목록에 노출됨 | 연속 장면 묶음과 확인 상태 표시, 세부 ID는 확인 창에 배치 |
| 인물 확인 | 웹 선택창의 모양이 다르고 설명과 조작이 흩어짐 | 사진과 확인 폼의 크기 조정, 이전과 다음 사진 이동 |
| 질문 | 입력과 선택 항목이 목록의 위쪽을 차지함 | 질문 작업을 별도 창에서 수행 |
| 답변 | DB 설명과 AI 설명의 반복, 근거 번호 버튼 다수 | 짧은 답변, 집계 요약, 사진이 보이는 근거와 접는 상세 |

변경 전 캡처를 준비하면서 검사기가 로딩 중인 화면을 완료 상태로 다루는 문제를 발견해 완료 대기를 추가했다. 모바일 웹의 사진 편집은 HTTPS 또는 localhost가 필요하므로 Android localhost 포트 전달로 같은 서버에 연결한다. 보안 컨텍스트 검사를 제품 코드에서 해제하지 않는다.

## 증빙

`tools/verify-ui-audit.ps1`로 실제 Android 캡처와 화면 측정 JSON을 수집했다. 원본은 `evidence/private/ui-audit`에 보관하고 실행별 경로와 해시는 `evidence/ui-audit/before.json`, `after.json`에 기록했다. 검사 실패 기록도 각 실행 폴더에 보존한다.

배포 릴리스는 `20261108162427b12e30`이며 주소는 https://daejinha.pythonanywhere.com 이다. 기존 게시글 3개와 사진을 보존하고 공식 YOLO 버스 사진을 테스트 게시글 1개로 등록했다. 기존 DB 모델은 유지했고 이력 테이블을 추가했다. 이력 사진은 릴리스가 바뀌어도 보존되는 공유 비공개 경로를 사용한다.

전체 화면은 `evidence/ui-audit/review.html`, 전후 비교는 `evidence/private/ui-audit/review/comparison.png`에서 확인한다. 운영 결과는 `evidence/ui-audit/deployment.json`, `evidence/ui-audit/cloud/verification.json`, `evidence/cloud/verification.json`, `evidence/history/cloud-runtime.json`에 기록했다. UI 검사 전용 고정 AI 응답과 실제 운영 LLM 호출 결과를 구분한다. 기존 Word 보고서 갱신과 웹캠 실측은 이 UI 검사 범위에 포함하지 않는다.


현재 화면은 인물 카드에서 영상별 이력과 질문으로 연결된다. 신규 공개 영상 8개, 등록 인물 3개 프로필과 미등록 인물 2개 영상에 대한 실제 분석을 운영에 추가했다. 대표 장면 46장을 추가했으며 전체 관측 사진은 83장이다. 원본 촬영일 미상과 분석일을 구분한다. 얼굴 후보는 확인 전까지 확정하지 않고, 정답 ID를 대조한 시연 확인은 별도 표시한다. 두 Android 화면 크기에서 얼굴 비교와 실제 확인 저장을 검증했다. 운영 AI 답변에서 발견한 영상 길이 오인과 내부 ID 노출은 회귀 테스트와 응답 검사로 차단했다. 최종 운영 답변은 영상 2개와 근거 사진 2장을 확인했다. 최신 결과는 docs/testing/PERSON_EXPERIENCE.md와 evidence/ui-audit/person-experience.json에 있다. Word 보고서는 이번 작업에 포함하지 않았다.
