# 감시 시스템 화면 재편

11월 9일 현재 주 메뉴는 관측 기록, 인물 확인, AI 질문이다. 현황의 전체 집계와 마지막 분석 시각을 날짜별 관측 목록에 합쳤다. 얼굴 비교는 인물 확인에서, 인물과 기간에 따른 기록 질의는 AI 질문에서 수행한다. 아래 11월 8일 내용은 이전 개편의 검증 기록이며 최신 메뉴 증빙은 `evidence/ui-audit/merged-navigation.json`에 정리한다.

2026년 11월 8일. 주 메뉴를 현황, 관측 기록, 인물 확인으로 정리한다. 기록 질문은 관측 목록과 인물별 버튼에서 실행한다. 기존 추가 기능 두 개의 표현과 사용 동선을 바꾸는 작업이며 별도의 세 번째 추가 기능으로 집계하지 않는다.

## 화면과 데이터

| 화면 | 웹 경로 | 내용 |
| --- | --- | --- |
| 현황 | `/` | 관측 사진, 선 통과, 후보 확인 대기, 수신 세션과 최근 장면 |
| 관측 기록 | `/detections/` | 실제 TrackingFrame 장면의 날짜 및 인물 조회, 근거 사진과 확인 창 |
| 인물 확인 | `/people/` | 인물 후보 검토, 확인 저장 및 인물별 이력으로 이동 |
| 기록 질문 | `/questions/` 및 관측 목록의 질문 버튼 | 조회 중인 기록에 질문하고 DB 집계와 근거 사진 확인 |
| 사진 보관함 | `/photos/`, 계정 메뉴에서 접근 | 기존 및 수동 사진과 공통평가 동기화 자료 보존 |

`GET /api/v1/history/overview/`는 동일한 DB 집계와 프로필 요약을 Android에 제공한다. 운영자 권한이 필요하고 응답은 캐시하지 않는다. 비회원 첫 화면은 서비스 안내를 보여준다. 관측 사진과 인물 및 추적 데이터는 운영자만 열람한다. 예전 블로그의 Post 목록을 감지 기록으로 재사용하던 경로를 없애고 `/detections/`가 실제 관측 화면을 열도록 연결했다. 기존 `/history/` 링크도 유지한다. 집계의 detection_posts는 실제 관측에 연결된 사진만 세며 기존 사진 보관함 전체 건수를 감지 건수로 취급하지 않는다.

수치는 전체 저장 기록 기준이다. 선 통과 건수, 추적 번호 수와 사람 수를 구분한다. 마지막 수신 시각은 서버가 받은 시각이며 카메라가 현재 연결됐다는 의미로 표시하지 않는다. 촬영 날짜가 없는 영상은 날짜 미상으로 유지한다. Android 날짜는 API 24에서도 한국 시간으로 표시한다.

## 평가 요구 보존

`PhotoBlogServer`, `PhotoViewer`, `YOLOv5` 구조를 유지한다. 기존 Post API의 필드와 사진 등록, 객체 종류의 첫 출현 및 재출현 전송, Android의 이미지 동기화와 PythonAnywhere 운영을 유지한다. 기존 게시글, 계정과 사진을 삭제하거나 재분류하지 않는다. 사진 편집과 수동 등록은 증거 기록 추가 도구로 제공한다. 데이터베이스 스키마 변경은 없다.

## 검증 기록

WSL 테스트는 새 집계에서 후보와 운영자 확인의 구분, 촬영 날짜 미상 보존, 비회원 및 다른 계정 접근 거부, HTML과 앱 API의 집계 일관성을 검사한다. 실제 Android 감사는 기본 크기와 작은 크기에서 새 첫 화면, 인물 이력과 독립 질문 화면을 추가 캡처하고 기존 사진 편집 및 게시 흐름도 다시 실행한다. UI 검사에서 사용하는 AI 응답은 고정 예제이며 실제 LLM 연결 검증과 구분한다.

실행 결과와 캡처 경로는 `evidence/ui-audit/after.json`, 최종 집계는 `evidence/ui-audit/summary.json`, 운영 배포 검증은 `evidence/ui-audit/deployment.json`에 기록한다. 보고서 Word 파일은 별도 최신화가 필요한 기존 진행본이다.

최종 검증: WSL Django 198개, 웹 단위 72개, Windows Android JVM 40개가 통과했다. Android Lint 오류는 0개이고 경고는 10개다. 두 크기의 앱 및 WebView 감사 4개와 실제 사진 작성 흐름 2개가 통과했다. 수정 후 UI 캡처는 110장, 작성 흐름 캡처는 추가 16장이다. 운영 릴리스는 20261108162427b12e30 이며 실제 운영자 집계 API와 LLM 생성도 확인했다.


320 CSS 픽셀 폭의 키보드 화면에서 질문 완료 버튼이 부모 영역에 일부 잘리는 문제를 수정했다. 입력 중에는 보조 필터와 예제 버튼을 접고 여백을 줄인다. 버튼의 위아래와 좌우 가장자리를 실제 터치 대상으로 확인해 화면 위치만 맞는 경우와 구분한다. Android 기본 뷰도 완료 버튼 전체가 보이는지 확인한다.


초기 얼굴 사진 복구 시점의 운영 이력은 실제 모델 검증 기록 37장, 프로필 2개, 추적 번호 23개와 선 통과 6건이었다. 이후 추가한 시연 자료의 최신 상태는 아래 인물 중심 개편 기록과 PERSON_EXPERIENCE.md에 정리했다. 처음 넣은 도식 이미지 16장이 실제 얼굴 사진보다 먼저 노출되는 문제를 확인해, 해당 시연 세션과 가상 프로필만 DB 백업 후 정리했다. 실제 모델 사진은 얼굴 위 디버그 문구가 없는 원본 영상 장면으로 교체하고 운영 API에서 37장 모두 해시를 대조했다. 실제 추적의 후보와 확인 상태, 촬영 날짜 미상, 기존 공개 게시글과 사진 및 계정을 보존했다. Edge에서도 이력 이미지는 원본 장면을 전송하고 평가에 필요한 감지 게시글과 결과 영상에는 검출 표시를 유지한다. WSL Edge 단위 테스트 30개와 실제 영상 78프레임 전송 검증이 통과했다. 최신 증빙은 evidence/history/cloud-face-repair.json과 evidence/history/verification.json이며, 이전 시연의 날짜 질의 및 LLM 검증은 evidence/history/cloud-demo.json에 과거 결과로 보존한다.


세 메뉴 재편 검증은 evidence/ui-audit/navigation.json에 정리했다. WSL Django 198개, 웹 72개, Android JVM 40개와 두 크기의 네이티브 및 모바일 웹 검사가 통과했다. 사진 추가부터 실제 업로드와 검색까지 각 크기에서 다시 확인했다. 운영 릴리스는 20261108162427b12e30이다. 실제 운영자 브라우저에서 세 메뉴, 실제 관측 사진, 기존 게시물의 비노출을 확인했고 캡처 경로와 해시를 기록했다.


현재 화면은 인물 카드에서 영상별 이력과 질문으로 연결된다. 신규 공개 영상 8개, 등록 인물 3개 프로필과 미등록 인물 2개 영상에 대한 실제 분석을 운영에 추가했다. 대표 장면 46장을 추가했으며 전체 관측 사진은 83장이다. 원본 촬영일 미상과 분석일을 구분한다. 얼굴 후보는 확인 전까지 확정하지 않고, 정답 ID를 대조한 시연 확인은 별도 표시한다. 두 Android 화면 크기에서 얼굴 비교와 실제 확인 저장을 검증했다. 운영 AI 답변에서 발견한 영상 길이 오인과 내부 ID 노출은 회귀 테스트와 응답 검사로 차단했다. 최종 운영 답변은 영상 2개와 근거 사진 2장을 확인했다. 최신 결과는 docs/testing/PERSON_EXPERIENCE.md와 evidence/ui-audit/person-experience.json에 있다. Word 보고서는 이번 작업에 포함하지 않았다.
