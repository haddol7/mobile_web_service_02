# 출입 영상 자료 확장

감시 시스템의 관측 자료에 ChokePoint 출입 영상 네 개를 추가한다. 같은 촬영의 다른 카메라를 새 원본으로 중복 계산하지 않고, 서로 다른 네 구간에서 카메라 하나씩을 선택했다. 원본은 [NICTA 공식 안내](https://arma.sourceforge.net/chokepoint/)와 [공식 Zenodo 배포본](https://zenodo.org/records/815657)을 사용한다.

| 화면 이름 | 원본 구간과 카메라 | 제공 이미지 수 |
| --- | --- | ---: |
| 출입구 1 입장 보행 구간 2 | P1E_S2_C2 | 2,369 |
| 출입구 1 퇴장 보행 구간 1 | P1L_S1_C1 | 3,558 |
| 출입구 2 혼잡 입장 구간 5 | P2E_S5_C2 | 806 |
| 출입구 2 혼잡 퇴장 구간 5 | P2L_S5_C2 | 755 |

원본 압축 파일은 총 1,452,192,540바이트다. 공식 MD5를 대조하고 선택한 카메라의 이미지 7,488장으로 800x600, 30fps 재생 영상을 만들었다. 변환 영상은 끝까지 디코딩해 프레임 수와 크기를 확인했다. 원본 번호에 누락이 있으므로 변환 영상의 재생 시각을 실제 촬영 시각으로 사용하지 않는다. 일반 구간의 정답 XML은 함께 보관하며, 공식 정답 묶음에 없는 S5 혼잡 구간에는 정답이 있다고 표시하지 않는다.

모델은 기존 YOLOv5, Norfair와 Buffalo L의 candidate-2 정책을 그대로 사용한다. 비교 대상은 기존 등록 프로필 다섯 개이며 새 학습은 없다. 원본별로 10에서 20장 간격으로 분석하고, 대표 사진은 시간 간격을 두어 고르되 몸 추적과 연결된 얼굴 장면을 우선한다. 등록 프로필 후보가 붙은 장면은 게시 대상으로 고르지 않으며 전체 분석의 후보 수는 원본 검증 기록에 남긴다. 이 선정 결과를 무작위 표본 정확도로 보고하지 않는다.

관측 사진은 기존 인증 API로 전송한다. 원본 촬영 시작 시각은 null로 유지하고 사람의 신원을 자동 확정하지 않는다. 원본 JPEG 파일명과 변환 영상 재생 위치를 사진별로 기록한다. 같은 실행과 프레임의 재전송이 새 사진을 만들지 않는지 확인한다. 기존 게시글과 대화 기록도 보존한다. 원본 영상과 사진, 임베딩 파일은 Git에서 제외되는 비공개 경로에 두며 이용 조건 원문과 변환 고지를 함께 보관한다.

RAG는 기존 31개 문서 벡터를 재사용하고 새 원본 네 개의 설명과 날짜 메타데이터만 추가한다. 사용자가 2026년 11월 9일 승인한 유료 임베딩 최대 1회 범위에서 실행하며, 사진과 얼굴 특징을 API에 보내지 않는다. 요청 시도를 기록해 실패 후 자동 재호출하지 않는다. 운영 검색 검증은 기존 질문 캐시와 cache_only:true 및 generate:false를 사용한다.

수집은 tools/expand_chokepoint_walk.py collect, 모델 분석은 analyze, 게시 준비는 prepare로 실행한다. tools/review_chokepoint_expansion.py는 실제 원본과 모델 상자를 별도 검토 이미지로 만든다. 이 검토 이미지는 검출기 입력이나 운영 사진으로 사용하지 않는다. tools/deployment/publish_chokepoint_expansion.py는 preflight, observations, embeddings 단계를 나누어 기존 색인 확인, 데이터 등록과 승인된 색인 갱신을 수행한다.

최종 검증은 WSL Ubuntu의 기존 프로젝트 가상환경과 실제 PythonAnywhere API 및 운영 브라우저에서 진행했다. 501프레임에서 얼굴 검출은 934건, 몸 추적에 연결된 얼굴은 527건이다. 반복 검출을 포함하며 사람 수가 아니다. 기존 등록 다섯 프로필에 연결된 얼굴 후보는 이 분석 구간에서 0건이었다. 대표 장면은 일반 구간 각각 14장과 혼잡 구간 각각 16장으로 총 60장이다. 운영에는 사진 270장, 영상 실행 35개, 세션 내부 추적 번호 171개가 있다. 추적 번호는 실제 사람 수와 방문 횟수가 아니다.

원본별 운영 조회와 기록 질문의 DB 집계를 대조했다. 재전송으로 새 사진이 생기지 않았고 기존 게시글 및 대화 기록은 보존됐다. 새 사진은 비로그인 요청에서 거부되고, 촬영 시각과 신원을 임의로 확정하지 않았다. 운영 브라우저에서 네 영상의 목록과 새 입장 영상의 실제 사진 및 미확인 상태를 확인하고 캡처했다.

색인은 35개 문서를 포함한다. 새 문서 네 개의 임베딩 요청은 1회이며 586토큰을 사용했다. 기존 31개 벡터와 질문 캐시를 보존했다. 기존 고정 검색 질문 세 개는 캐시 전용 검증에서 관련 출처를 찾았다. 검증 단계의 유료 API 요청과 LLM 생성은 각각 0회다. 새 영상에 대한 일반 질문의 답변 정확도를 이 고정 예제 결과로 주장하지 않는다.

증빙은 evidence/history/chokepoint-expanded-collection.json, chokepoint-expanded-inference.json, chokepoint-expanded-source-review.json, chokepoint-expanded-cloud.json, chokepoint-expanded-embedding-build.json 및 chokepoint-expanded-embedding-cloud.json에 있다. 전체 결과와 화면 해시는 같은 디렉터리의 chokepoint-expanded-summary.json에 기록한다. 원본과 운영 캡처는 evidence/private/cctv-walking/expanded에 보관한다.
