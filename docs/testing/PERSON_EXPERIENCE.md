# 인물 중심 화면과 시연 자료

2026년 11월 9일 작업 기록이다. 기존 추가 기능 두 개의 사용 흐름과 검증 자료를 보강했다.

## 화면

인물 확인은 등록 얼굴을 보여주는 카드에서 시작한다. 카드를 열면 해당 인물이 연결된 영상별 이력과 질문 버튼이 나온다. 얼굴 후보 비교는 접은 영역에서 열며 등록 사진과 관측 사진을 나란히 보여준다. 대시보드의 후보 검토 링크는 비교 영역을 바로 연다.

관측 목록은 연속 프레임을 사진별로 나열하지 않고 영상 실행별로 묶는다. 질문 검색도 한 영상의 최근 사진만 고르지 않고 여러 영상에서 근거를 모은다. 날짜 필터의 기본값은 분석일이다. 원본 촬영일 조회는 별도로 선택하며 날짜 미상 자료를 임의의 촬영일로 바꾸지 않는다.

Android는 네이티브 얼굴 카드, 인물별 이력, 얼굴 비교와 확인 저장을 제공한다. 모바일 웹을 앱 전체로 대체하지 않았다. 공통평가의 기존 Post API와 사진 동기화 및 업로드는 사진 보관함에서 유지한다.

## 실제 자료

이미 수집한 VoxCeleb2 자료 중 등록 인물 3명과 미등록 인물 2명을 사용했다. 각 등록 인물의 등록 영상과 두 조회 영상은 원본 영상 ID가 모두 다르다. 원본 ID가 다르다는 검증이며 서로 다른 날짜나 실제 방문을 증명하지는 않는다.

| 항목 | 결과 |
| --- | --- |
| 조회 원본 영상 | 8개 |
| 등록 얼굴 프로필 | 3개 |
| 실제 분석한 프레임 | 251개, 원본에서 4프레임 간격으로 처리 |
| 운영에 추가한 대표 사진 | 46장 |
| 같은 등록 인물의 재등장 | 3개 프로필 모두 두 원본 영상에서 후보 연결 |
| 미등록 인물 영상 | 2개, 등록 인물 후보 오연결 없음 |
| 원본 촬영일 | 미상으로 보존 |
| 모델 학습 | 없음 |

이 자료는 기능 시연을 위한 표본이며 기존 별도 인물 검증의 정확도 수치를 대체하지 않는다. 등록 사진도 조회 영상의 프레임을 재사용하지 않는다. 원본 영상과 참조 이미지 및 얼굴 특징은 Git에 포함하지 않는다.

인물 A의 두 영상과 인물 B의 한 영상에 대해서는 데이터셋의 정답 인물 ID를 대조했다. 해당 확인은 `review_basis=dataset`으로 저장하고 화면에 `시연 정답 확인`으로 표시한다. 모델이 자동으로 신원을 확정한 결과나 실제 운영자의 현장 확인으로 설명하지 않는다. 나머지 후보는 비교하고 확인하는 흐름을 시연할 수 있도록 유지한다.

## 시간과 질문의 정확성

2026년 11월 10일 본인 웹캠 촬영 세 건을 추가했다. 운영자가 확인한 추적은 4개, 남은 후보는 0개다. 이는 한 사람을 세 번 별도로 촬영한 기록이며 서로 다른 사람 수나 방문 횟수가 아니다. 실시간 입력에는 촬영 건수와 카메라 안내를 표시하고 존재하지 않는 영상 재생 초는 표시하지 않는다. 확인 전 캡처는 보고서 B19와 B20, 이후 상태는 B30이다.

생성 답변의 수치는 근거에 숫자가 존재하는지만 보지 않고 추적, 통과, 확인 프로필과 출처 등의 해당 필드에 대응해 검사한다. 분석일과 알려진 촬영일도 구분한다. 지원하는 표현에 대한 보수적 검사이며 모든 자연어 주장의 진위를 보장하지 않는다. 외부 생성 실패 시 유형과 경과 시간만 기록하고 인증값이나 제공자 응답 본문은 노출하지 않는다. 기록 조회에 근거 사진을 유지하고 대체 답변과 실제 생성 답변의 상태를 구분한다.

영상 내 위치는 OpenCV가 실제 읽은 원본 프레임 위치로 계산한다. 프레임 건너뛰기를 사용하는 경우에도 원본 위치가 맞아야 한다. 사진의 원본 크기와 얼굴 영역을 따로 저장해 해당 관측의 얼굴만 제한된 크기로 보여준다.

실제 운영 AI 답변 검사에서 영상 내 위치를 전체 영상 길이처럼 설명하고 내부 근거 ID를 본문에 노출하는 사례를 발견했다. LLM 입력에는 `video_position_seconds`라는 이름을 쓰고 의미를 명시했다. 위치 수치를 영상 길이나 체류 시간으로 설명하거나 긴 내부 ID를 답변 본문에 넣으면 생성 결과를 사용하지 않고 DB 조회 설명을 보여준다. 근거 ID는 별도 배열에서 검증하고 사용자 화면은 사진으로 연결한다. 해당 오류를 재현하는 회귀 테스트도 추가했다.

질문은 인물 필터가 초기화된 뒤에 전송할 수 있다. 인물 상세에서 넘어온 조건이 준비되기 전에 전체 자료에 대한 질문이 전송되지 않도록 한다.

## 재현과 증빙

WSL 프로젝트 가상환경에서 다음 도구를 실행한다.

```text
python tools/prepare_monitoring_showcase.py
python tools/populate_monitoring_showcase.py
python tools/populate_monitoring_showcase.py --cloud
cd PhotoBlogServer
python tools/verify_content.py
```

Android 빌드와 실제 화면 검사는 Windows에서 실행한다.

```powershell
.\PhotoViewer\tools\verify-android.ps1
.\tools\verify-ui-audit.ps1 -Phase after -Sizes small,regular
```

실제 모델 추론은 `evidence/history/showcase-inference.json`, 운영 자료와 질문 근거는 `evidence/history/showcase-cloud.json`에 기록했다. 화면 캡처 경로와 해시는 `evidence/ui-audit/after.json`과 최종 인물 화면 검증 기록에 보관한다. UI 감사에서 사용하는 고정 AI 응답과 운영 서버의 실제 AI 생성 검증은 구분한다.

마이그레이션 0006은 기존 테이블에 등록 사진, 확인 근거, 원본 사진 크기, 얼굴 영역을 추가한다. 기존 Post 필드와 계정 및 사진을 바꾸지 않는다. 최초 전체 배포에서 DB 백업 후 적용했다. 이후 화면 수정과 답변 검증 수정은 공식 Files 및 Webapps API로 지정한 파일만 백업 후 반영했다. 콘솔을 사용한 것처럼 기록하지 않는다. `active.json`의 기본 릴리스와 `frontend_overlay`, `verified_patch`를 함께 추적하며 각각 검증된 로컬 패키지와 복구 파일을 유지한다.
