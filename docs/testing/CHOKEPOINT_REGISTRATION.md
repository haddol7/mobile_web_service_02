# ChokePoint 인물 등록

공식 Still.tar.xz의 Neutral 및 Smile 사진 58장을 사용해 인물 29명을 등록한다. 파일 이름의 ID를 그대로 사용하고 화면 이름은 출입 인물 01과 같은 별칭으로 표시한다. 실제 이름을 추정하지 않는다. 공식 ID에는 0008이 없고 0030이 포함되므로 화면 번호를 임의로 다시 매기지 않는다.

원본은 [ChokePoint 공식 배포본](https://zenodo.org/records/815657)이며 게시된 MD5 2efcd4010d19e811cce144a614ea82a2와 대조했다. 원본과 등록용 파생 사진에 이용 조건과 자르기 및 크기 변경 고지를 보관한다. 인물마다 중립 표정과 미소 사진 두 장을 처리했고 58장 모두 등록 가능한 얼굴을 검출했다. 전체 29쌍의 파생 사진을 나란히 배열해 얼굴 선택과 ID 파일명을 검토했다.

새 29명과 기존 등록 인물 다섯 명을 합친 갤러리는 34명이다. 기존 Buffalo L과 candidate-2 판정 기준을 유지하며 모델 학습이나 미세 조정은 없다. 등록용 정지영상과 조회용 출입 영상은 별도 자료다. 로컬 얼굴 특징과 원본은 Git이나 LLM 입력에 포함하지 않는다.

등록 후 분석 대상은 기존 P1E_S1_C1 첫 1,200개 제공 이미지 구간, P1E_S2_C2, P1L_S1_C1, P2E_S5_C2와 P2L_S5_C2다. YOLOv5와 Norfair는 두 제공 프레임 간격으로 처리하고 얼굴은 처리 프레임 다섯 장마다 비교한다. 재생 영상 기준 몸 추적은 약 15fps, 얼굴 비교는 약 3fps다. 낮은 빈도의 사진 표본만으로 추적 번호가 서로 다른 사람에게 이어지는 문제를 줄이기 위한 구성이다.

일반 구간은 공식 XML의 양쪽 눈 좌표가 한 검출 얼굴 안에 함께 들어가는 경우에만 정답 ID를 대응시킨다. 두 사람의 정답이 같은 검출 영역에 들어가거나 눈 한쪽만 들어가면 정답을 지정하지 않는다. 한 몸 추적 번호에 서로 다른 정답 ID가 나타나거나 여러 얼굴 후보가 섞이면 시연 정답 확인 대상으로 고르지 않는다. 최소 두 개의 정답 대응이 같은 ID이고 모델 후보도 같은 경우에만 기존 dataset 확인 API를 사용한다. 정답 ID를 모델의 입력이나 유사도 계산에 전달하지 않는다.

혼잡 S5 구간에는 공식 정답이 없어 모델 후보를 확인된 인물로 자동 바꾸지 않는다. 등록 사진과 모델 후보 비교, 정답에 따른 시연 확인을 구분한다. 분석일은 실제 실행 시각이며 원본 촬영 시각을 임의로 추가하지 않는다.

등록 후 분석은 새 실행으로 보존하고 원본 출처 키를 유지한다. 따라서 기존 원본 영상 다섯 개를 다시 처리한 것이며 새 촬영 원본 다섯 개가 추가된 것으로 집계하지 않는다. 기존 관측 사진, 게시글과 대화 기록을 보존한다.

웹과 Android는 관측 이력이 없더라도 등록 사진이 있는 인물을 카드로 표시한다. 관측이 없는 경우 등록 완료와 발견 대기를 표시하고 영상 수를 0으로 유지한다. 등록 사진도 이력도 없는 시험용 빈 항목은 일반 카드 목록에 섞지 않는다.

재현 도구는 tools/collect_chokepoint_people.py, tools/register_chokepoint_people.py와 tools/deployment/publish_chokepoint_people.py다. 첫 도구는 등록 원본을 수집하고 두 번째 도구의 enroll, analyze, prepare 단계는 얼굴 등록, 실제 모델 분석과 게시 자료를 만든다. 운영 도구는 인증된 기존 이력 API, 참조 사진 API와 정답 확인 API를 사용한다. tools/review_chokepoint_people.py는 등록 사진 전체 검토용 이미지를 만든다.

정답 대응의 애매함과 추적 ID 혼합을 다루는 tools/test_chokepoint_identity.py의 WSL 단위 검사 네 개가 통과했다. 등록 얼굴의 첫 관측 전 표시를 추가한 WSL 서버 검사에서는 Django 테스트 245개와 실제 로컬 HTTP 검사 15개가 통과했다. 웹 단위 검사 76개와 Windows Android 빌드 및 JVM 검사 40개도 통과했다. 실제 모델의 후보 판정 수치와 화면 검사는 별도의 실행 기록으로 보관한다.

사용자는 새 재분석 기록 다섯 개의 텍스트 메타데이터를 위한 임베딩 최대 1회를 별도로 승인했다. 기존 벡터와 질문 캐시를 재사용하며 사진과 얼굴 특징은 보내지 않는다. 운영 조회 검증은 generate:false와 cache_only:true를 사용해 추가 과금을 막는다.

2026년 11월 9일 운영 반영 결과, 새 29명 모두 등록 사진과 발견 이력이 있다. 28명은 후보를 포함해 두 개 이상의 서로 다른 원본 영상에 연결됐고, 인물 02는 한 영상에서 후보가 나왔다. 원본 다섯 개의 재분석에서 총 4,343프레임을 처리하고 얼굴을 1,207회 검출했다. 얼굴 검출 수에는 같은 사람의 반복 검출이 포함된다.

공식 정답이 있는 일반 구간 세 개에서 정답 ID와 대응된 얼굴 비교는 359건이다. 모델 후보 일치 358건, 판단 보류 1건이며 다른 ID를 선택한 경우는 0건이었다. 이는 검출된 얼굴 중 양쪽 눈 좌표를 유일하게 대응시킨 표본의 결과다. 전체 원본의 얼굴 검출률이나 혼잡 영상의 정확도를 뜻하지 않는다. P1E_S2_C2와 P1L_S1_C1에서는 각각 25명의 올바른 후보가 몸 추적과 연결됐다. 이 중 반복 정답과 모델 후보가 일치한 몸 추적 61개를 시연 정답 확인으로 저장했다.

대표 관측 사진 230장을 추가해 운영 사진은 500장, 분석 실행은 40개가 됐다. 등록 사진 접근 권한, 중복 재전송 시 새 사진이 생기지 않는 동작, 원본 촬영일 미상 유지와 기존 게시글 및 대화 보존을 실제 PythonAnywhere API에서 검증했다. 인물별 영상 수와 DB 기반 질문 결과가 29명 모두 일치했다. 인물 카드와 얼굴 비교, 영상별 이력은 운영 브라우저에서도 확인했다.

새 메타데이터 문서 다섯 개는 text-embedding-3-small의 512차원 벡터로 추가했다. 실제 요청은 승인된 1회이며 사용량은 1,681토큰이다. 기존 35개 벡터를 재사용해 현재 색인은 40개 문서다. 기존 질문 캐시로 의미 검색 세 가지를 확인했으며 검증 과정의 추가 유료 호출과 LLM 생성은 0회다.

웹 배포 릴리스는 20261108214913fe1503이다. Windows Android 에뮬레이터의 작은 화면과 일반 화면에서 네이티브 및 WebView 검사가 통과했다. 서버 검증 명령은 WSL 프로젝트 가상환경의 `python PhotoBlogServer/tools/verify_content.py`, 정답 대응 검증 명령은 `python -m unittest discover -s tools -p test_chokepoint_identity.py -v`다.

실행 증빙은 evidence/history/chokepoint-people-enrollment.json, chokepoint-people-analysis.json, chokepoint-people-cloud.json, chokepoint-people-embedding-cloud.json과 chokepoint-people-summary.json에 보관한다. 등록 사진 검토 및 운영 화면 캡처는 evidence/private/cctv-walking/people 아래에 보관한다. 여기에는 enrollment-review.jpg, production-people.jpg, production-person.jpg와 production-comparison.jpg가 있다.
