공통평가 02 다른 PC 이어가기
기준 2026년 11월 10일 한국시간

이 폴더에는 이번 노트북에서 새로 확보한 증빙과 보고서 반영 자료를 담았다. 기존 프로젝트 소스와 Word 보고서는 다른 PC의 작업본을 사용한다.

다른 PC에서 할 일

1. 기존 「모바일웹서비스 프로젝트 공통평가 02_수행 결과 보고서.docx」를 연다.
2. 01_보고서_삽입문구.txt를 참고해 평가표 3번의 확인 결과를 갱신한다. 본문 B08의 영상 입력 증빙 다음에 실시간 웹캠 결과와 02_웹캠_증빙의 웹캠_실시간_검출.png를 삽입한다. 새 캡처에는 얼굴과 실내가 보이므로 공개 GitHub에 올릴 이미지인지 검토한다.
3. 평가표의 원본 요구사항, 이름과 학번, 평가자 판정 칸을 보존한다. Word에서 저장한 뒤 모든 페이지와 그림 배치를 확인한다.
4. 최신 소스와 갱신한 보고서를 별도 GitHub 저장소 haddol7/mobile_web_service_02에 반영하고 원격에서 확인한다. 제출 전 비밀정보와 공개 범위를 확인한다. 이번 비교에서 원격 main의 HEAD는 262418c9e16187042755770f7c6ba1d2e3489373이었고 작업본 보고서와 바이트가 달랐다.

이번 노트북에서 완료한 검증

- 11월 10일 Acer HD User Facing 웹캠을 WSL2 Ubuntu의 /dev/video0에 연결했다. 원본 YOLOv5 v7.0으로 사람을 실시간 검출했고, 최신 프레임에 person 0.71과 검출 상자가 표시된다. 실제 입력 640×480, MJPEG, CPU 환경이다.
- WSL2에서 Ubuntu 24.04.2 LTS와 Python 3.12.3을 재사용했다. 전용 가상환경을 만들고 pip check, 매니페스트 615개 파일, Buffalo L CPU 로딩, 등록 사진 34명 73장의 읽기를 확인했다.
- 원본 YOLO 정지 이미지에서 사람 4명과 버스 1대를 검출했고, 동봉 영상은 별도 로컬 분석에서 240프레임을 처리했다.
- Django 전체 250개와 노트북 단위 테스트 9개가 통과했다. 별도 SQLite DB에서 /api_root/, /api_root/Post/, /photos/는 모두 HTTP 200을 반환했다. 초기 전체 테스트의 경로 환경변수를 바로잡고 재실행한 결과다.
- Windows Android SDK 36, Build Tools 36.1.0, ADB를 확인했고 동봉 APK의 v2 서명을 검증했다. 이번 노트북에서 앱 실행은 별도 항목이다.
- 웹캠은 WSL에서 분리한 뒤 Windows에서 다시 인식됐다. 운영 서버 검증과 유료 API 사용 건수는 이번 작업에서 각각 0회다.

자료 위치

02_웹캠_증빙에는 제출에 사용할 최신 원본 프레임과 검증 기록, 로그, 재현 보조 스크립트가 있다.
03_노트북_검증에는 WSL 환경 점검, 테스트 로그와 정지 이미지 결과가 있다. 초기_환경_검증.json의 웹캠 미연결과 WSL 2.4.13은 업데이트 전 상태이며 최종 웹캠 상태는 02의 웹캠_검증.json을 참고한다.
SHA256SUMS.txt로 전송 중 파일 변경 여부를 확인할 수 있다.

재실행이 필요한 경우

기존 common02 작업본을 Windows에 두고 Ubuntu에서 /mnt 경로로 실행한다. Windows에서 각 PC의 실제 카메라 BUSID를 확인한다. 이번 노트북의 BUSID는 1-6이었다.
02_웹캠_증빙의 webcam_mjpeg_capture.py를 기존 프로젝트의 .local/laptop/에 복사한 뒤 WSL에서 common02 루트로 이동해 아래 명령을 실행한다.

OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 WEBCAM_EVIDENCE_PREFER_OBJECTS=1 ~/.venvs/mobile_web_service_02/bin/python .local/laptop/webcam_mjpeg_capture.py

보조 스크립트는 tools/run_edge.py의 원본 해시 검사를 거쳐 카메라 0번의 입력 형식을 MJPEG로 지정하고 실제 검출 프레임을 저장한다.
